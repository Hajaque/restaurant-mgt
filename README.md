## Features

- **Dashboard** (`/`): totals for menu items, orders (active, completed, cancelled), revenue from completed orders, and the five most recent orders.
- **Menu management** (`/menu/`): list, search, filter by category and availability, add, edit and delete menu items.
- **Pricing rule**: desserts carry a 5% service charge, calculated by the `selling_price` property on the `MenuItem` model.
- **Orders**: each order holds several order items; the order total is calculated automatically.
- **Order history safety**: an order item stores a copy of the item name and unit price at the time of ordering, so later menu changes do not alter old bills.
- **Django administration** (`/admin/`): manage menu items, orders and order items, with bulk actions to complete or cancel orders.

## Getting Started

### 1. Create and activate a virtual environment

```bash
python -m venv venv

# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

### 2. Install Django

```bash
pip install django
```

### 3. Go to the project folder

```bash
cd restaurant
```

The folder must contain `manage.py`.

### 4. Apply the database migrations

```bash
python manage.py migrate
```

### 5. Create an administrator account (to use `/admin/`)

```bash
python manage.py createsuperuser
```

### 6. Run the development server

```bash
python manage.py runserver
```

Open <http://127.0.0.1:8000/> in your browser.

## Data Models

- **MenuItem**: name, description, category (Food, Drink, Dessert), price, availability, created and updated times. Property `selling_price` adds 5% to desserts.
- **Order**: customer name, table number, status (Active, Completed, Cancelled), timestamps. Properties `subtotal` and `total_amount`; methods `complete_order()` and `cancel_order()`.
- **OrderItem**: belongs to one `Order` and one `MenuItem`; stores item name, quantity and unit price. Property `line_total` = quantity × unit price. A menu item can appear only once per order.

Relationships: one `Order` has many `OrderItem` records (`order.items.all()`), and each `OrderItem` refers to a `MenuItem` (protected from deletion while used in an order).

## Django Architecture (MVT)

| Part | Role | In this project |
|------|------|-----------------|
| Model | Data and database tables | `models.py` |
| View | Logic that handles a request | `views.py` |
| Template | HTML presentation | `templates/restaurant/*.html` |

Request flow: browser request → root `urls.py` → app `urls.py` → view → model (database query) → template → HTML response.

## Object-Oriented Concepts Used

- **Classes and objects**: `MenuItem`, `Order`, `OrderItem` and `MenuItemForm` are classes; database rows are objects.
- **Inheritance**: `models.Model`, `forms.ModelForm`, `admin.ModelAdmin`, `admin.TabularInline` and `AppConfig` are extended by our own classes.
- **Encapsulation**: calculations and state changes live inside the classes (`selling_price`, `line_total`, `complete_order()`), and validators protect field values.
- **Polymorphism**: `__str__` is overridden so each object displays readable text.
- **Association**: `ForeignKey` links `OrderItem` to `Order` and `MenuItem`.
